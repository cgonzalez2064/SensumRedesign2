# Project portfolio PDF — how to replace it

The "Conversemos sobre tu proyecto" button at the end of the "Tipos de
proyectos" section on the home page downloads this folder's PDF instead
of scrolling to the contact form. Right now that file is a **dummy
placeholder** — generated content, not real project photos or examples
— clearly labeled as such on every page of the PDF itself, so visitors
can't mistake it for the real thing.

## Current file

`sensum-portafolio-proyectos.pdf` — a 2-page placeholder: a cover page
reusing only the already-approved "Tipos de proyectos" category names
and the business's published contact details (no invented projects,
photos, clients, or stats), and a second page with these same swap
instructions. It was generated by a one-off script
(`generate_placeholder_pdf.py`, kept outside this site's published
folders — ask the developer if you need to regenerate a similar
placeholder; it should never be reused to produce the *real* portfolio).

## To replace it with the real portfolio

1. Get the final portfolio PDF from the client (real project photos,
   descriptions, etc. — with their confirmation it's OK to publish).
2. **Simplest path — keep the same filename:** overwrite this file,
   keeping the exact name `sensum-portafolio-proyectos.pdf`. Nothing
   else needs to change — the button in `index.html` already points
   here.
3. **If you'd rather use the client's own filename:** keep both files'
   names as you like, but then open `index.html`, find the HTML
   comment that starts with `PORTFOLIO PDF —` right above the
   `projects-cta` button, and update the `href` (and the `download`
   attribute, if you want the saved filename to match) to point at the
   new file.
4. Open the site, click the button, and confirm the correct PDF
   downloads (not just opens the placeholder from a cache — hard-refresh
   if needed).
5. Once replaced, you may also want to update/remove the portfolio
   section in `CONTENT-APPROVAL.md` that tracks this as a placeholder.

## Why a download instead of opening in a new tab

The button uses the HTML `download` attribute, which — for a same-origin
file like this one — tells the browser to save the file directly rather
than navigate to it. If you'd prefer it open in a new tab instead,
remove the `download` attribute from that button in `index.html` (see
the same HTML comment referenced above).
